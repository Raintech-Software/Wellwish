## Findings

1. ✅ **Fixed the same day (Phase 9C):** the family inbox and a live bell are built; an admin's cancel or new time now reaches the family's open app at once (it stayed "Partner assigned" on Home). Was: **The family has no inbox yet.** Booking confirmed, partner assigned, reminders, steps, completed and cancel / refund messages are saved for the family, but the patient app only shows them as **push notifications**, and push is off until the Firebase key is added (KEYS-AND-ACCOUNTS). Until then a family sees updates only while the app is open (those are instant). The bell on Home has no screen behind it ("the inbox comes later"). → Decide: build the family inbox before release, or rely on push once Firebase is set up.
2. ✅ **Done:** Minimum notice set back to 3 hours (16 Oct). Was: **Settings → Minimum notice is 0** in this dev database (left from earlier testing so visits can start within 2 hours). Set it back to 3 hours before real use.
3. Refunds of the *simulated* test payments show FAILED at Razorpay (they aren't real payments): expected, dev data only. The real test payment's refund was accepted by Razorpay.
4. Not a bug: when the family books for **themselves** no SMS is sent (they get it in the app); a family member with their own phone gets the SMS.
5. Not a bug: a temporary partner's app only opens their one booking (`/me` → `temporaryBookingId`); the full job lists answer 403.
